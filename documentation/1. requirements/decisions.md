# Decisions

Numbered, never renumbered. Each decision is stated as a rule, without the example it was asked with. The agency side of the same design is in `mwanachama-backend-agency/documentation/1. requirements/compute-decisions.md`. Open questions stay on the page they belong to, with the page's proposed answer.

| # | Decision | Consequence | Settles | Issue | Who |
|---|---|---|---|---|---|
| 1 | The repo is named `mwanachama-backend-compute` | The module path is `github.com/aosanya/mwanachama-backend-compute` | Name | ISS-1 | Owner 2026-11-17 |
| 2 | The repo is public | Every example, fixture and test value is invented: no real names, emails or figures | Visibility | ISS-1 | Owner 2026-11-17 |
| 3 | It is a pure library: no database, no HTTP, no import of any mwanachama repo | It computes values and does not schedule or run workloads | Scope | ISS-1 | Owner 2026-11-17 |
| 4 | A release tag is cut when the first working version passes its tests | Agencies pin to release tags | Release | ISS-1 | Owner 2026-11-17 |
| 5 | A function body is one line of text written like a spreadsheet formula, and that text is the only stored and published form | A builder or an AI writes text; a reviewer reads text | Formula form | ISS-2 | Owner 2026-11-17 |
| 6 | A formula is saved in one standard shape: hand-typed spacing is rewritten on save | Equal formulas have equal text, and a respaced formula is not a change to the publication's content hash. Parsing the printed form gives back the same tree | Standard shape | ISS-2 | Owner 2026-11-17 |
| 7 | A tool may show and edit a formula as blocks; the blocks generate the same text and are never a second stored form | The language is kept small enough for every part of it to have a block | Block view | ISS-3 | Owner 2026-11-17 |
| 8 | A function's input rules and checks belong to its definition, not to its caller, and all problems with a set of inputs are returned at once before any calculation | Every caller (a step, a bulk run, an AI tool) is held to the same rules and gets the same problem list | Input checks | ISS-2 | Owner 2026-11-17 |
| 9 | Bulk runs are designed in from the start: one formula over many rows, a bad row never fails the batch, and a batch gives what each row alone gives | The batch page and the bulk test pages are written against one row shape | Bulk | ISS-5 | Owner 2026-11-17 |
| 10 | A library function is called by name and version; a publication records the versions it uses and keeps them until its builder changes them; a fix ships as a new version and a published version is never edited or removed | One running host serves every version in use; the builder is told when a newer version exists and can move to it in one step | Library versions | ISS-18 | Owner 2026-11-17 |
| 11 | A known-wrong library version keeps running, with a loud notice and a one-step upgrade. Only the platform owner may stop a version found unsafe, for every agency at once, and each affected step then follows its own failure choice. There is no automatic stop after a set time | What counts as unsafe, how a stop and its reason are recorded, and what people see are still open on the versioning page | Wrong versions | ISS-18 | Owner 2026-11-17 |
| 12 | A formula that breaks a rule or goes over a limit can be saved as a draft that cannot be published, with a plain sentence saying what is wrong and where | A refusal "at save" in the test pages is read as "stored as a draft with the sentence attached; publishing refuses" | Unfinished formulas | ISS-11 | Owner 2026-11-17 |
| 13 | When a total is shared, each share is cut down to the currency's smallest unit, the payout is the sum of the shares, and the left-over stays in the account the payout came from | Nobody gets an extra unit; there is no rounding account and no random choice; the payout never exceeds the total | Left-over of a split | ISS-10 | Owner 2026-11-17 |
| 14 | Where a formula names no rounding, halves round up | A formula may name another rule; which other modes are offered is still open on the exact-money page | Default rounding | ISS-10 | Owner 2026-11-17 |
| 15 | Each agency sets the number of decimal places of its currency, and every amount, rounding and share follows it | Cases that assumed 2 places need the setting; a formula using two currencies must say which currency each amount is in | Currency places | ISS-10 | Owner 2026-11-17 |
| 16 | Each agency sets the largest number of rows one batch may hold. A batch over the agency's limit is refused whole before any row is worked out | The limit is a setting of the agency and not a constant of the library; a ceiling above which no agency may set it is still open on the batch page | Batch size | ISS-5 | Owner 2026-11-17 |
| 17 | A bulk run has two stages: a calculation batch that works out every row and finishes as a whole, then an actualization batch that posts or releases the results | The calculation batch changes nothing real, so it can be confirmed, held, repeated or cancelled before the actualization batch starts. The library only does the calculation stage | Two-stage batch | ISS-5 | Owner 2026-11-17 |
| 18 | Check reads the formula text alone and covers everything about it: limits and shapes, unknown names and functions, values of the wrong kind, nesting depth and cost. Validate covers only the values given when the formula runs | A formula that fails Check is saved as a draft that cannot be published (decision 12). Check needs no numbers, so it can run on every keystroke and on save | Check and Validate | ISS-2 | Owner 2026-11-17 |
| 19 | A runaway formula is stopped by a cost limit, a count of the work it does. The library sets no time limit of its own | The same input always gives the same outcome on every machine, so a result is repeatable and a test cannot pass and fail on the same input. A formula over its limit is refused by Check on save, or stopped at run time with the same plain sentence; a row stopped at run time is a failed calculation and follows the step's failure choice. Whether and how a host's own cancel is honoured is open on the batch page | Slow work | ISS-4 | Owner 2026-11-17 |
| 20 | The agency decides the rounding rule. Wherever a result is a number, the builder is offered the list of rounding rules to apply to it | Half up stays the rule when none is chosen (decision 14). The list is proposed as down, up, half up, half down and half even, and down is needed anyway by decision 13. Whether an agency can also change its own default from half up is open on the exact-money page | Rounding rules | ISS-10 | Owner 2026-11-17 |
| 21 | The agency decides how a division that does not end is handled inside a calculation: the number of digits kept before the final rounding is an agency setting | The same setting and the same input always give the same figure. The default (20 digits is proposed) and the range an agency may choose from are open on the exact-money page | Endless division | ISS-10 | Owner 2026-11-17 |
| 22 | Whether an input may be negative is declared by the function for each input, as part of its input rules. An input that does not declare it refuses negatives | Nothing goes negative by accident, and the problem list names the input and gives a plain sentence. A balance can be declared to allow negatives while a rate does not | Negative inputs | ISS-2 | Owner 2026-11-17 |
| 23 | The library runs formulas on its own engine, written in this repo on the Go standard library: its own tree, reader, standard-shape printer and evaluator | One tree serves the reader, the printer, the block view and the evaluator, so nothing is translated to or from another engine's form. A runaway formula is stopped by the engine's own cost count, and the library depends on no expression engine. The design takes ideas from cel-go and expr-lang (a separate checking pass, errors with a position, a program planned once and run many times, a cost estimate) and copies none of their code | Engine | ISS-4 | Owner 2026-11-17 |
| 24 | A call written with no arguments is part of the language: Parse reads an empty argument list, and Check refuses it. An unknown name gives unknown-function and a known name gives wrong-argument-count | A call to `now()`, `random()`, `env()`, `exec()` or `read_file()` gets the same sentence as any other unknown name, and the sentence names the function. There is no separate syntax problem for empty brackets | Empty argument list | ISS-74 | Owner 2026-11-17 |
